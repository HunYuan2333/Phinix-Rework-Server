## 实现与不变量

- 正向确认绑定窗口实际显示的不可变快照实例，已有 metadata 携带版本，不修改固定 Common 或 SDK。旧的无观察依据正向 API 拒绝，撤回/取消仍可用；客户端后台更新不能替玩家确认新报价。
- 服务端将最后报价变更版本持久化，接受同一报价上的先后确认；缺失/过期/未来版本拒绝，不修改报价、接受标志或交付。拒绝后给调用方同步报价，仍需用户重新确认。
- 版本属于操作指纹，同 ID 换版本冲突；已提交原结果不重执行业务。历史缺版本操作沿用旧指纹，升级后仍可回原结果，不能借此重新接受已撤销的 consent。
- 无版本证据的旧活动记录在监听前迁移：报价保留、未绑定确认清除、快照递增；终态/交付记录保留。现有 DB 的迁移状态及 migration result 同事务，失败后禁止继续提供内存权威，恢复后只迁移一次。封存 XML 不重写。
- 依赖方向只涉及 Trade.Client 与 Trade.Server 的联合行为，宿主无业务恢复分支，不新增包，不改四仓库 gitlink/vendor。
