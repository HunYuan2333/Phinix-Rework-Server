## 1. 依据、范围与固定约束

本路线以两份基础评估为依据，并接入新增静态性能和容错评估：

- [服务端现状评估](Server-Assessment-2026-10-14.md)：构建、客户端契约、交易可靠性、协议接入、SQLite 与运维缺口。
- [服务端协议边界与无密码身份升级评估](Server-Protocol-and-Passwordless-Identity.md)：Legacy 翻译边界、统一业务语义、无密码身份与迁移约束。
- [静态性能审计](Server-Static-Performance-Audit-2026-10-14.md)：同步热路径、锁、分配、字节预算及动态验证计划。
- [容错与可恢复性评估](Server-Fault-Tolerance-and-Recoverability-2026-10-14.md)：故障传播、资产事务、保存/停机、身份泄露与恢复证据。

测试建设和质量门槛参见 [测试与质量保障专项规划](Server-Test-and-Quality-Assurance-Plan.md)。L1～L4 从 P0 建设并逐阶段扩展，完整任务见本路线 §8，不把基础测试堆到 P6。

实施优先级与验收范围以本文件 §0/§14 的最新用户调整为准；协议/身份的底线仍遵循用户补充约束：所有旧兼容妥协局限于 Legacy adapter；玩家保持自动、无密码身份。前者关于普通密码登录的泛化讨论不作为产品默认方案。

范围包括 Server 宿主、Common 契约、Chat/Trade 服务端插件、必要客户端协议/身份/回执改动，以及老 Phinix adapter。服务端已经是 .NET 10，沿现有项目分切片改造。客户端 UI/引擎迁移不是本路线主线；真实交付与凭据生命周期验证仍是联合验收责任。

硬约束：

1. Legacy adapter 只翻译、校验可表达性并拒绝不支持的功能；不拥有另一套业务账本，不裁决退款或交付。
2. 新业务不判断 Legacy/V2，不携带旧包/token/旧凭据字段；各协议保持同一成功、失败、整批、持久提交和幂等语义。
3. 协议级别与能力属于会话/adapter；能力不等于权限。业务只接收统一意图、稳定主体与授权事实。
4. 用户不创建密码或手工操作私钥。正常升级保留玩家 UUID、显示名、交易记录和自动登录。
5. 一项物品失败整批失败；已经派发但结果未知不自动返还、重发或改协议。
6. 资产状态、操作结果与 delivery outbox 同事务提交，成功回执在 COMMIT 后发送。
7. 插件平权；宿主提供通用服务，不添加 Chat/Trade 专属启动/恢复分支。
8. 固定各消费者 Common gitlink；不自动追踪最新子模块，不编辑 vendored protobuf 锁定与源码。

## 5. 现有 Rework 登录怎么办

**当前决定：继续既有 UDP / ClientKey，不执行现代身份切换，不退役旧登录。** 下述迁移步骤保留为后续 TODO 的历史方案，不能据此要求本轮部署者配置 TLS。SV-64 本轮决策为保留现状；SV-70 仅推进必要的 UDP 客户端版本发布；SV-71 的现代凭据迁移与 SV-72 整体延期，资产恢复验收仍须完成。TQ-40 现代安全通道实机、TQ-50/51 现代 TLS 混合子集及 TQ-60/70 现代身份切换子集不阻塞当前 UDP 交付；既有自动化证据仍有效，其他验收要求不降低。


**需要 Client/Common/Server 的联合升级。** 只改服务器无法让已有客户端理解新握手、安全传输和凭据绑定。工坊承担客户端分发，服务端 binary、配置与数据库迁移仍由部署者执行。

正常玩家路径：工坊更新客户端 → 连接已准备好的目标服务器 → 客户端读取原 ClientKey 并自动创建/保存新凭据 → 在安全通道中完成旧身份映射 → 保留原 UUID 与交易关联 → 后续自动登录。历史认证字段解析完全留在 Legacy adapter；新身份验证与业务不读取旧规则。

当前不要求同一时刻全体在线升级，也不承诺长期兼容未升级 Rework。按候选联测、工坊可获得、服务端切换、旧登录退役四步规划；实际先后可随兼容验证调整。发布时必须验证客户端新版本连接未切换服务器的行为，不能在认证失败后悄悄降级。

工坊发布后仍可能有离线、锁版本、本地包和更新失败的客户端。切换最低版本后这些端应得到可表达的更新提示/拒绝；旧端不能解析的新错误由 adapter 转成旧失败包，无法提示时明示连接失败。不能自动创建新身份来绕过版本门槛。

凭据文件保护单列验收：源码默认路径为 `PhinixCredentials.bin`，实际启动传入路径与运行目录需实施时核对；凭据不得放在会被工坊制品替换的目录。更新模组不等于删除用户身份文件。

本阶段暂缓决定：最低客户端版本、切换日期、是否采用短暂双入口、过渡期限、证书部署方案、回退窗口。不因暂缓决定而阻塞 P0～P3 的准备与实现，也不把临时兼容扩散到新业务。发布前必须确定；“届时再说”不等于无期限保留旧凭据。

## 6. 联合验收与实施记账

每个任务记录状态（待实施/实施中/源码通过/自动测试通过/联机待测/已验收）、关联提交、实际执行命令、输入版本及剩余限制。当前所有任务待实施；基础评估、静态性能/恢复评估和本路线完成不算产品功能完成。

每一垂直切片同时完成契约、实现、必要 adapter、错误回执、持久化影响和测试；禁止先在业务层塞兼容分支、最后再搬回 adapter。P1 做 L1/L2 与短宿主故障，P2 做真网络协议，P3 做真实 SQLite/outbox/定点强杀，P4 做安全身份，P5 做独立 Legacy golden/混合客户端；P6 负责真实游戏、专用系统故障和 RC 扩大验证。

验收至少覆盖：

- 新端/未升级 Rework/原版端：版本与 feature 缺失、握手重放、epoch、身份错配、权限不足。
- 物品：全批/部分缺引用、重复/跨 owner、codec/预览不匹配、空报价、超预算。
- 资产：重复/乱序/迟到请求、未知结果查询、成交/取消/outbox 原子性、强杀、磁盘满、重复 ACK。
- 身份：自动注册/登录/迁移、UUID 保留、凭据丢失/损坏、服务器信任失败、轮换/撤销与迁移抢占。
- 运行：慢插件/DB、队列满、扩展加载失败、stdin EOF、SIGTERM、重复 stop、恢复与回退。
- 发行：正式/候选组合、干净输出、工坊文件更新与凭据保留、部署者服务端更新。

有实际证据才扩大可靠性交付和兼容承诺；不能用关闭全部业务、降低结果标准或吞异常换取完成状态。
